# 术语表

> 代码中的表名、字段名、类型名、枚举值与本表对齐。新术语先进此表再进代码。

| 术语 | 英文/代码 | 定义 |
|---|---|---|
| 家庭 | family | 组织实体，账户体系的顶层单位 |
| 用户 | user | 自然人，跨家庭唯一；Phase 0 以小程序 openid 识别（升个体户后补 unionid 跨端打通） |
| 成员 | member | 用户与家庭的关系边，携带角色与称谓 |
| 虚拟成员 | virtual member | 无登录能力的成员（孩子），`user_id` 为 NULL，可认领转正 |
| 称谓 | relation_label | 奶奶/外公等，用于展示与推送文案 |
| 认领 | claim | 虚拟成员绑定真实微信账号，档案无缝转正 |
| 日程 | schedule | 有固定时间地点的事件（课程/接送/活动/提醒），进日历 |
| 日程实例 | schedule_instance | RRULE 物化出的单次发生，提醒/冲突/统计都打在实例上 |
| 责任人 | owner | 日程/任务的执行责任方（成员） |
| 任务 | task | 重复性目标行为（阅读/跳绳），进打卡 |
| 打卡 | checkin | 任务的一次提交（拍照/计时/计数），可由父母代打 |
| 触达级别 | notify level | strong（错过即事故）/ medium（当天看到即可）/ weak（不推） |
| 确认回执 | receipt | 用户点击触达消息打开小程序即回执；**无已读概念** |
| 升级 | escalation | 强触达 15min 无回执→应用内待办红点；30min 无回执→备份联系人（短信兜底升个体户后恢复） |
| 主理人模式 | owner mode | 由管理员设置的家庭录入权限模式：限定仅指定成员可录入，其余父母只读+评论 |
| 成长时间线 | timeline | 打卡/里程碑/照片按孩子自动沉淀的时间流 |
| 家庭圈 | family circle | V3 功能：3–10 家庭的邀请制结盟群 |
| 事件流 | events_stream | 打卡完成/连续天数等事件，千人千面激励的预留钩子 |
| 鸡娃 | — | 目标用户群俗称，不进代码与 UI 文案 |

## 易混概念

- **日程 vs 任务**：日程=时间事件（谁在何时何地）；任务=重复目标行为。录入入口必须二选一，不允许混淆。
- **角色 vs 称谓**：role 决定权限与视角（代码枚举）；relation_label 只用于展示与文案（自由文本）。
