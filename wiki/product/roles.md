# 角色模型与权限

## 核心模型

```
用户(User) ──< 成员关系(Membership: role + relation_label) >── 家庭(Family)
```

- 账号是"人"，家庭是"组织"，成员关系是"边"。**不做家庭共用账号**。
- 一人可属多个家庭（祖辈挂多个子女家庭、离异父母共挂孩子、家教服务多家）。
- 角色是成员关系上的属性，**不是账号全局属性**。同一人可在不同家庭有不同角色。

## 角色与权限（V1）

| 能力 | admin | parent | grandparent | child |
|---|---|---|---|---|
| 成员管理/家庭设置 | ✓ | – | – | – |
| 日程/任务录入编辑 | ✓ | ✓（可选主理人模式限定） | – | – |
| 今日视图 + 接收提醒 | ✓ | ✓ | ✓ | – |
| 打卡提交 | ✓ | ✓ | 协助上传 | ✓（父母设备切换身份/代打） |
| 成长档案查看 | ✓ | ✓ | ✓ | – |
| 变更反馈（"去不了"） | ✓ | ✓ | ✓ | – |

家教/阿姨等外部成员 V2 再做。

## 三条注册路径

- **父母**：微信授权（openid，Phase 0 单端够用）+ 手机号可选填（脱敏存，预留短信通道）。
- **祖辈**：邀请卡片 → 打开小程序 → 微信授权（openid）→ 选称谓。全程 <30 秒，无密码，无取号。手机号**可选填**（脱敏存、暂不验证，升个体户启用短信后再作为兜底通道）。
- **孩子**：虚拟成员（影子档案），父母创建，不登录。`members.user_id` 可空，长大后一键认领转正。

## 视角决定规则

- 视角由登录账号在当前家庭的角色**自动决定**，无手动切换开关。
- 父母：四 Tab（今日/日历/打卡/家庭）。祖辈：无 Tab，首屏=聚合今日视图（跨家庭聚合）。
- 唯一例外：成员详情页「预览 Ta 的视图」，供主理人核对祖辈首屏呈现。

## 关键规则

- 家庭创建者默认为 **admin**；每个家庭 ≥1 名管理员，**末位管理员不可降级或退出**。
- 成员管理仅 admin：可改成员角色（含设置/取消其他成员管理员）、配置身份（称谓）、移除成员。虚拟成员（孩子）角色固定为 child，仅可配置称谓。
- 称谓预设：真实成员 爸爸/妈妈/爷爷/奶奶/姥姥/姥爷/叔叔/阿姨；孩子 儿子/女儿；均为自由文本可自定义（见 [glossary](glossary.md)：relation_label 只用于展示与文案）。注意：预设里的「阿姨」只是称谓标签，**外部成员账号**（家教/阿姨）仍是 V2 范围。
- 祖辈**无编辑权**，以"去不了"反馈回路替代（触发强触达通知责任父母改分工）。
- 移除成员/退出家庭**不影响孩子档案**（档案归属孩子 member_id，不归属家庭）。
