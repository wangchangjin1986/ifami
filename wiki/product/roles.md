# 角色模型与权限

## 核心模型

```
用户(User) ──< 成员关系(Membership: role + relation_label) >── 家庭(Family)
```

- 账号是"人"，家庭是"组织"，成员关系是"边"。**不做家庭共用账号**。
- 数据模型仍可表达一人多家庭，既有多家庭历史关系不迁移、不截断；本轮新创建/加入和使用路径只允许一个有效家庭归属，不提供多家庭切换或再次加入入口。
- 角色是成员关系上的属性，**不是账号全局属性**；本轮仍按当前有效家庭的 membership 判断视角与权限。

## 角色与权限（V1）

| 能力 | admin | parent | grandparent | child |
|---|---|---|---|---|
| 成员管理/家庭设置 | ✓ | – | – | – |
| 日程/任务录入编辑 | ✓ | – | – | – |
| 今日视图 + 接收提醒 | ✓ | ✓ | ✓ | – |
| 打卡提交 | ✓ | ✓ | 协助上传 | ✓（父母设备切换身份/代打） |
| 成长档案查看 | ✓ | ✓ | ✓ | – |
| 变更反馈（"去不了"） | ✓ | ✓ | ✓ | – |

不新增独立外部成员角色；本轮阿姨加入复用 `grandparent` 权限与照护人视图，家教等其他外部成员后置。

## 三条注册路径

- **父母**：微信授权（openid，Phase 0 单端够用）+ 手机号可选填（脱敏存，预留短信通道）。
- **祖辈 / 阿姨 / 另一位家长（家人加入）**：打开小程序 → 「加入家人的家庭」→ 当面扫管理员的「家庭加入码」（24 小时有效）→ 选身份（家长/祖辈/阿姨）→ 选称谓 → 确认加入（显示家庭名称与身份）→ 微信授权（openid）。全程 <30 秒，无密码，无取号。手机号**可选填**（脱敏存、暂不验证，升个体户启用短信后再作为兜底通道）。本轮只支持用户归属一个家庭，不增加多家庭加入或往返入口。
- **孩子**：虚拟成员（影子档案），父母创建，不登录。`members.user_id` 可空，长大后一键认领转正。

## 视角决定规则

- 视角由登录账号在当前家庭的角色**自动决定**，无手动切换开关。
- 父母：四 Tab（今日/日历/打卡/家庭）；非管理员父母可查看家庭安排、参与打卡，无录入/编辑/成员管理入口。祖辈/阿姨：无 Tab，首屏=当前家庭本人分工今日视图。
- 唯一例外：成员详情页「预览 Ta 的视图」，供管理员核对祖辈首屏呈现。

## 关键规则

- 家庭创建者默认为 **admin**；每个家庭 ≥1 名管理员，**末位管理员不可降级或退出**。
- 成员管理与录入编辑仅 admin：可改成员角色（含设置/取消其他成员管理员）、配置身份（称谓）、移除成员，并录入/编辑日程与打卡任务。虚拟成员（孩子）角色固定为 child，仅可配置称谓。
- 称谓预设：真实成员 爸爸/妈妈/爷爷/奶奶/姥姥/姥爷/叔叔/阿姨；孩子 儿子/女儿；均为自由文本可自定义（见 [glossary](glossary.md)：relation_label 只用于展示与文案）。阿姨作为加入身份时仍持久化为 `grandparent`，称谓不参与权限判断。
- 祖辈/阿姨**无编辑权**，且只可查看和执行 `owner_member_id` 为本人的事项；以"去不了"反馈回路替代编辑（触发强触达通知责任父母改分工）。
- 移除成员/退出家庭**不影响孩子档案**（档案归属孩子 member_id，不归属家庭）。
