# ADR-005：AI 录入——AI 只产草稿，人确认入库

## 决策

拍照导入日程（R2.6）、自然语言速记（R2.8）等 AI 录入通道，输出一律为**草稿**，必须经管理员确认后才写入 `schedules`。识别失败/无法辨认的行原样展示，提供手动补录。实现见 [技术方案设计 §5.5](../../docs/技术方案设计.md)。

## 背景

- 课表识别走火山方舟·豆包多模态模型，准确率不可能 100%。错误日程直接入库比没有 AI 更糟（奶奶会被导到错误地点）。
- "AI 草稿 → 人确认"也是信任建立过程：用户逐条核对后，对产品的信任来自"我确认过"。
- 2026-11-03：拍照导入替代「复制上一周」模板化录入，成为新家庭初始化录入主路径（P0）；微信聊天记录导入（R2.7）不做，群图先存相册再走相册选图。

## 关键推论

1. 模型输出必须带 `confidence`（high/low）与 `uncertain` 字段列表，低置信行在确认屏标黄；每条带 `source_text` 原文片段，供「对照原图」修改。
2. Prompt 约束输出固定 JSON schema：`{image_kind, items:[{title, weekdays[], date?, start_time, end_time?, until?, location, note, child_name?, confidence, uncertain[], source_text, unreadable}]}`——schema 之外的输出视为该图识别失败。
3. 模型原始输出不直接给前端：服务端做确定性归一化（时间校验、学校作息合并为 `school` 在校块、自动生成接放学、孩子匹配、RRULE 生成），规则必须单测。
4. 超时与降级：单图 45s 超时、重试 1 次；失败回退「安排一件事」手动表单，小程序保留已选图片可重新上传。
5. 批量入库走一次事务：经 schedule 模块 `CreateSchedulesBatch` 写入；任何一行失败整体回滚，冲突逐条返回。
6. 原图仅用于识别：Phase 0 落本地临时目录，任务终态即删（见 ADR-006 修订记录）；识别结果加密存储。
7. 同一解析管线服务所有入口（拍照/相册、后续 NL 文本），入口只负责拿到原始材料。

## 优先级与验证

P0（初始化录入主路径）。上线前用 50+ 张真实课表建准确率基线（前置事项 §6）；线上以草稿确认率、字段修改率作为持续准确率指标。
