# ADR-004：激励后置与事件流钩子

## 决策

V1 不建任何激励体系（积分/心愿/宠物/对战）。打卡模块只保留"记录+提醒+可视化反馈"（进步曲线、连续天数是事实陈述，不是激励）。激励按"千人千面"方向后置到 V2。

## 背景

- 激励方案是家长的"育儿主权"：不同家庭手段不同（积分/实物/游戏时长），不同孩子对激励敏感度不同，产品替家庭选一套是越界。
- 重游戏化会模糊工具定位，也增加家长对"孩子盯屏幕"的抵触。
- 待验证假设：**纯记录型打卡的 30 天留存率**。数据难看则激励中台提前。

## 关键推论（架构上必须留的钩子）

1. `checkins` 写入后同步写 `events_stream`（checkin_done / streak / goal_hit / schedule_done）。V1 **只写不消费**。
2. 数据模型预留成长值/激励元数据字段位（暂不加列，V2 加列即可，历史事件可重放）。
3. V2 千人千面激励 = events_stream 的新消费者：家庭可配置方案（积分制/实物/特权时长自选），同家庭不同孩子可不同方案。
4. UI 红线：不出现积分、勋章、等级等视觉元素（见 [../product/red-lines.md](../product/red-lines.md)）。

## 禁止事项

- 不要在打卡完成页加任何"奖励感"视觉（撒花、金币、升级动画）。"✅ 已完成 · 连续 5 天"的朴素陈述是上限。
