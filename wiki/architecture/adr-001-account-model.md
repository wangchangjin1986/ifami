# ADR-001：账号体系——人/家庭/成员三元组与孩子虚拟成员

## 决策

账号是"人"（User），家庭是"组织"（Family），成员关系是"边"（Membership: role + relation_label）。孩子是虚拟成员：`members.user_id` 可空，长大认领转正。

## 背景

- 鸡娃家庭是多角色协作：爸妈分工、祖辈接送、离异重组、祖辈挂多个子女家庭——"一个家庭一个共用账号"无法表达这些关系，且推送无法到人、权限无法分级。
- 未成年人大多没有自己的微信/手机，且个保法要求监护人同意——代管结构天然满足。

## 关键推论（写代码时必须遵守）

1. 一人可属多家庭：`members` UNIQUE(family_id, user_id)，user_id 可空（虚拟成员）。
2. 角色在成员关系上，不在用户上——视角、权限、触达路由全部按 `(user_id, family_id)` 查 membership。
3. 孩子档案归属 `member_id` 而非 family_id——父母退出/离异重组不丢数据；认领时把 user_id 回填即可，历史数据零迁移。
4. 推送通道身份独立成表 `identities(user_id, channel, appid, openid, unionid)`——同一祖辈的小程序 openid、服务号 openid、短信手机号是三个通道身份。`unionid` 预留可空，openid 仍作 channel 内唯一键。
5. 微信侧地基：Phase 0 纯个人主体无开放平台，仅小程序一端，用 **openid** 即可（单端内唯一）。升个体户后注册开放平台，绑定小程序 + 服务号，回填 `unionid` 做跨端身份合并（届时补一次 openid→unionid 去重）。

## 替代方案（已否决）

- 家庭共用一个大号：推送无法到人、权限无法分级、微信生态落不了地。
- 孩子独立账号：合规风险（未成年人注册）+ 现实中孩子没手机。
