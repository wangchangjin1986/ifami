# 小程序规范

## 结构与工程

- 原生小程序，不引入跨端框架。主包只放 4 个 Tab 页 + 打卡流；家庭管理/时间线/周报走分包。
- 页面与 `app.json` pages 数组对应；新页面同时更新该数组与 [../product/roles.md](../product/roles.md) 的视角规则。
- 设计 token 与 `prototype/index.html` 保持一致（`app.wxss` 已落一份）；改视觉先改原型。

## 视角规则（重要）

- **祖辈无 Tab**：登录后按 `(user_id, family_id)` 的 membership 角色决定落地页。祖辈 → 全屏今日聚合视图；父母 → 四 Tab。
- 实现方式：不渲染 tabBar 而用自定义首页（原生 tabBar 无法按角色动态增删，祖辈路径用 `wx.reLaunch` 到独立页面）。
- 祖辈路径全程不出现"注册/登录/账号"字样。
- 大字模式：祖辈默认开（约 1.3 倍字号）；设置里可开关。

## 能力使用

- `getPhoneNumber`：祖辈入驻必选步骤；调用失败降级手动输入。
- 订阅消息只作补充通道（一次性订阅，不能依赖）；主触达通道是服务号。
- `chooseMessageFile`：微信聊天记录导入课表的入口（需用户主动触发，不能自动）。
- 打卡照片上传前先压缩，上传后等后端内容安全检测通过再展示（见红线第 9 条）。

## 表单与输入（真机踩坑后的硬规范）

- **input 一律用 `model:value` 双向绑定**，禁止 `value + bindinput` 受控写法——每次击键 setData 回写会打断真机中文输入法的拼音组合，表现为"无法输入"（英文键盘和模拟器不暴露此问题）。
- **原生 input 在 flex 容器里高度会塌陷**（`.card` 即 flex column），表现为"太小、点不出光标"；`app.wxss` 已全局 `input { min-height: 88rpx }`，新增输入框不要绕过它。
- 表单结构对齐原型 `.field`（label + 控件）模式。

## 兼容与发布

- 后端接口兼容矩阵记录在 `miniapp/COMPAT.md`，发版前核对。
- 发布走 miniprogram-ci 或开发者工具上传 → 体验版 → 提审 → 全量。Phase 0 用体验版即可。
- **代码改动必须重新上传体验版才在真机生效**；手机端删小程序重进避免旧包缓存。真机排障用开发者工具「真机调试」（Wxml/Console 实时可见），不要盲猜。
