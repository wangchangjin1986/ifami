# V1 信息架构（IA）

> 对应 [V1-需求列表.md](V1-需求列表.md)。原则：**角色自适应导航**——同一个小程序，父母看到四 Tab，祖辈只见聚合今日视图；不让祖辈学习"切换家庭/视图"等概念。

## 1. 导航结构（按角色）

- **父母**：底部 Tab = `今日` / `日历` / `打卡` / `家庭`
- **祖辈**：无 Tab。首屏 = 聚合今日视图；右上角仅保留"设置"（大字模式开关、通知通道状态）
- **孩子**：无独立端。在父母设备上经打卡流程的身份选择进入
- **视角无手动开关**：视图由登录账号在当前家庭的角色（`members.role`）自动决定；角色是成员关系上的属性，同一人可在不同家庭有不同角色。唯一例外是成员详情页的「预览 Ta 的视图」——供主理人核对祖辈首屏的实际呈现（字号、备注、提醒是否到位），也是排查"长辈说没看到提醒"的第一手工具。

## 3. 三张主屏线框

### 3.1 祖辈今日视图（首屏，无 Tab）

```
┌─────────────────────────┐
│  今天 10月26日 星期一    │
│ ┌─────────────────────┐ │
│ │ ⏰ 16:30  接乐乐放学  │ │
│ │ 📍 实验二小 东门     │ │
│ │ 🎒 带：水壶、外套    │ │
│ └─────────────────────┘ │
│ ┌─────────────────────┐ │
│ │ ⏰ 17:30  送钢琴课    │ │
│ │ 📍 音悦琴行 3楼      │ │
│ └─────────────────────┘ │
│  明天 · 07:30 送乐乐上学 │
│ ┌───────────────────┐   │
│ │  📞 有事打给儿子    │   │ ← 人工兜底出口
│ └───────────────────┘   │
└─────────────────────────┘
```

设计要点：每屏 ≤3 件事；携带物品备注前置（老人最怕忘带东西）；电话按钮比任何交互优化都重要；"明天"只露一行。

### 3.2 父母周视图（日历 Tab 默认屏）

```
┌─────────────────────────┐
│ 乐乐家 ▾           ＋   │
│ 孩子: [全部] [乐乐] [果果]│
│       一    二    三    四 │
│ 14-16  ·     ·     ·    │ ← 每 2 小时一个时段
│ 16-18 乐·妈 乐·妈 乐·奶 ──│    格子=孩子·责任人
│ 18-20 乐·妈 果·妈 乐·奶 ──│
│ ─────────────────────── │
│ ⚠️ 周三：奶奶 17:30 冲突  │ ← 冲突前置到视图层
│    钢琴课 × 接果果        │
│    [调整分工]             │
│ ─────────────────────── │
│  今日   日历   打卡   家庭│
└─────────────────────────┘
```

设计要点：周视图是「每 2 小时一个时段 × 周一到周日」的时间网格，按孩子筛选查看；格子放「孩子 · 责任人」，回答"谁在哪个时段接送/陪课、谁撞车"，点开看课名详情；冲突警告可直接进入调整分工流程。

### 3.3 打卡流程（三步 ≤15 秒）

```
屏① 任务列表          屏② 身份+方式         屏③ 完成反馈
┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│ 今日打卡      │   │ 为谁打卡？    │   │ ✅ 阅读已完成  │
│ ○ 阅读 20分钟 │ → │ ┌────┐┌────┐ │ → │ ⏱ 20 分钟    │
│ ○ 跳绳 100个  │   │ │乐乐││果果│ │   │ 📅 连续 5 天  │
│ ● 练琴 ✓妈妈  │   │ └────┘└────┘ │   │ [再打一个]    │
│   代打        │   │ [📷拍照][⏱计时]│   │              │
└──────────────┘   └──────────────┘   └──────────────┘
```

设计要点：屏②选孩子与选方式合一屏；屏③"连续 N 天"是记录陈述（事实反馈），不是激励手段，符合激励后置边界；"再打一个"收拢多任务连续提交路径。

### 3.4 录入设计（工具税主战场）

**权限**：默认父母均可录入/编辑；家庭设置可选"主理人模式"限定录入人（R1.6）。祖辈无编辑权，以"无法执行/需调整"一键反馈替代（R2.10）——执行端给反馈回路，不给编辑权限。

**录入人全量视图（S12 管理视图）**：周视图回答"时间上谁有空档"，管理视图回答"事项上都在跑什么"：

```
┌─────────────────────────┐
│  管理 · 全部安排      ＋ │
│  乐乐 ───────────────── │
│  🎹 钢琴  周三 17:30     │
│     音悦琴行 · 接送: 奶奶 │
│  📖 阅读  每天 20 分钟   │
│     打卡任务 · 责任: 妈妈 │
│  果果 ───────────────── │
│  🏊 游泳  周六 10:00     │
│     蓝旗游泳 · 责任: 爸爸 │
│  ─────────────────────  │
│ [按孩子] [按机构] [已暂停]│
└─────────────────────────┘
```

（V2 方向：此视图是课时包管理/续费提醒的天然载体。）

**日程与任务的模型区分**：日程 = 有固定时间地点的事件（进日历，走强触达）；任务 = 重复性目标行为（进打卡，走中等级提醒）。「＋」按下先二选一："安排一件事 / 创建打卡任务"，各带一句话说明；选错可转换。

**四条录入通道**（对应 R2.5–R2.8）：手动表单+模板（P0 兜底）→ 拍照识别课表（P1，魔法时刻）→ 微信聊天记录导入（P1）→ 自然语言速记（P2）。

S3 创建屏顶部通道切换：`[手动填写 | 拍照识别 | 从微信导入]`。

拍照识别确认屏（AI 只产草稿，人确认才入库）：

## 4. 关键流程

### F1 邀请入驻（祖辈 ≤3 步）
```
微信聊天[邀请卡片] → S9 一键授权 → 选称谓(奶奶/爷爷/外公…) → 完成，落地 S1 今日视图
```

### F2 创建日程 → 触达生效
```
S2/S1[＋] → S3 填写(类型/重复/孩子/责任人/备注) → 冲突检测(即时提示) → 保存
→ 后台：按触达级别注册提醒任务（责任人通道路由，见 PRD §6）
```

### F3 打卡
```
S4 → S5(选孩子→方式→提交) → 完成页 → 事件流记录(打卡完成/连续天数)
   → 沉淀至 S11 时间线(P1) → 为千人千面激励预留事件钩子
```

### F4 强触达升级（后台，无界面）
```
日程临近 → 订阅消息（带小程序跳转） → 15min 无回执 → 应用内待办红点 → 30min 无回执 → 通知备份联系人(配偶)的订阅消息
```

## 5. 设计红线（界面层）

- 任何页面不出现跨家庭/跨孩子的对比、榜单、排名元素
- 祖辈路径全程无"注册/登录/账号"字样——只有"加入家庭"
- 不出现积分、勋章等激励视觉元素（V1 边界）
