# V1 需求列表（家庭协作工具）

> 对应 PRD §5 路线图 V1 阶段。不考虑变现，目标只有一个：解决家庭协作的真实问题。界面层见 [V1-信息架构.md](V1-信息架构.md)。
> 优先级定义：**P0** = 闭环必需，缺了产品不成立；**P1** = 显著提升留存/体验，可晚 2–4 周；**V2+** = 明确后置。

## 0. V1 要回答的用户问题（JTBD）

| # | 用户问题 | 对应模块 |
|---|---|---|
| Q1 | "今晚谁接娃、周几有什么课"——排课与接送分工靠群里吼，经常撞车 | M2 日历分工 |
| Q2 | 打卡坚持不下来，催作业靠吼，过程无记录、无反馈 | M3 打卡记录 |
| Q3 | 祖辈不知道"今天该干嘛"，反复打电话问 | M2 今日视图 + M4 触达 |
| Q4 | 关键提醒送达不到（微信群里被刷走） | M4 触达中枢 |
| Q5 | 孩子的成长数据散落在各处，想回头看没有 | M5 成长时间线（雏形） |
| Q6 | 多孩、多家庭（离异/祖辈挂多家）管理混乱 | M1 家庭与成员 |

## M1 家庭与成员（P0）

| ID | 需求 | 验收标准 | 优先级 |
|---|---|---|---|
| R1.1 | 创建家庭：微信授权 → 命名家庭 → 成为管理员 | 全程 ≤30 秒；每个家庭 ≥1 名管理员，末位管理员不可退出 | P0 |
| R1.2 | 邀请成员：生成邀请卡片微信分享，被邀请人一键微信授权 + 选称谓；手机号可选填（脱敏存，预留短信通道） | 祖辈入驻 ≤3 步；邀请链接 7 天有效；手机号暂不验证 | P0 |
| R1.3 | 添加孩子（虚拟成员）：姓名/生日/年级/手机号可选 | 无需孩子侧任何操作；支持多孩；数据模型 `user_id` 可空 | P0 |
| R1.4 | 多家庭支持：父母侧家庭切换器；祖辈默认**聚合今日视图**（不暴露"切换"概念） | 祖辈首屏聚合所有家庭的今日任务，按时间排序 | P0 |
| R1.5 | 成员管理：管理员可改成员角色（含设置/取消其他成员的管理员身份）、配置身份（称谓）、移除成员；身份提供常用预设（爸爸/妈妈/爷爷/奶奶/姥姥/姥爷/叔叔/阿姨等），支持自定义 | 退出/被移除不影响孩子档案（档案归属孩子，见 PRD §4 归属规则）；末位管理员不可降级或退出；虚拟成员（孩子）角色固定为 child，仅可配置身份 | P0 |
| R1.6 | 录入权限配置：默认父母角色均可录入/编辑；管理员可选**主理人模式**——限定仅指定成员可录入，其余父母只读+评论 | 默认开放，开关在家庭设置；主理人模式下非主理人可查看全量但不可编辑 | P1 |

## M2 家庭日历与分工（P0）

| ID | 需求 | 验收标准 | 优先级 |
|---|---|---|---|
| R2.1 | 日程创建：类型（课程/接送/活动/提醒）、重复规则（每周课表）、绑定孩子、**责任人**、地点、携带物品备注 | 创建"周三 17:00 奶奶接乐乐送钢琴课（带琴谱）" ≤20 秒 | P0 |
| R2.2 | 冲突检测：同一孩子时间重叠、同一责任人时间重叠时给出警告 | 创建时即时提示，允许强制保存（有些冲突是真实的） | P0 |
| R2.3 | 今日视图：时间线式"今天/明天"，祖辈默认首屏；大字模式；每项含时间/地点/责任人/备注 | 祖辈打开小程序 1 屏内看到"今天该干嘛"；字体 ≥18sp 等效 | P0 |
| R2.4 | 周视图：父母排课与查看一周全貌（每 2 小时时段 × 周一到周日的时间网格，格子显示「孩子 · 责任人」）；月视图：学期总览与单次事项（比赛/考级/出游）的撞课规划，打卡坚持月历（R3.4 的呈现形态） | 周视图支持按孩子筛选，P0；月视图 P1 | P0 / P1 |
| R2.5 | 模板化批量录入：每周固定课（课表式）一次录入全学期生效；"复制上周"快捷操作 | 录入一学期钢琴课（每周三）≤3 次操作 | P0 |
| R2.6 | 课表拍照识别：拍机构/学校课表 → AI 解析为结构化日程草稿 → 逐条确认入库，识别失败行原样展示可手补 | AI 只产草稿，人确认才入库；手动兜底永远可用 | P1（激活魔法时刻候选，种子期专项验证对激活率的拉动） |
| R2.7 | 微信聊天记录导入：`chooseMessageFile` 选取群聊中的课表图/通知文件 → 进入识别/解析流程 | 无需先存相册 | P1 |
| R2.8 | 自然语言速记："周三下午5点奶奶接乐乐" → 解析建日程 | 解析失败回退到手动表单并预填已识别字段 | P2 |
| R2.9 | 管理视图（录入人全量视图）：所有重复课程与打卡任务的列表总览，支持编辑/暂停/归档；按孩子/机构分组、统计为 P1 增强 | 主理人单屏看到全部分工与任务；简版（列表+编辑）P0 | P0 简版 / P1 增强 |
| R2.10 | 执行端变更反馈：祖辈/执行人对日程一键"无法执行/需调整" → 强触达通知责任父母改分工 | 祖辈无编辑权，以反馈回路替代 | P1 |

## M3 打卡（激励后置）

| ID | 需求 | 验收标准 | 优先级 |
|---|---|---|---|
| R3.1 | 任务模板：内置阅读/跳绳/练琴/英语等 + 自定义（名称/目标量/频次/责任父母）；支持一键批量启用多个模板 | 创建单个任务 ≤15 秒；批量启用 5 个模板任务 ≤30 秒 | P0 |
| R3.2 | 打卡提交：拍照/计时/计数三种方式；父母设备上切换孩子身份提交；家长代打 | 完成一次打卡提交 ≤15 秒 | P0 |
| R3.3 | 打卡提醒：到点未完成提醒**责任父母**（孩子无账号，不直接触达孩子） | 提醒时间可配置；经小程序订阅消息 | P0 |
| R3.4 | 进步曲线：按任务的周/月趋势与坚持轨迹，**只和自己比** | 定位为记录的可视化反馈，非激励手段；不出现任何跨家庭/跨孩子对比 | P1 |

**激励缺口（有意保留）**：积分/心愿/游戏化等激励手段**整体后置**。理由：激励方案是家长的"育儿主权"——不同家庭手段不同（积分/实物/游戏时长），不同孩子对激励的敏感度也不同，产品不宜替家庭选一套。但 V1 必须在架构上留钩子：

- 打卡完成、连续天数、目标达成等事件从第一天进入事件流；
- 数据模型预留成长值/激励元数据字段位；
- 未来按"千人千面激励"方向建设：家庭可配置激励方案（积分制/实物奖励/特权时长自选），同一家庭可对不同孩子配不同方案。见 PRD §5 路线图。

## M4 触达中枢（P0，工程最重模块）

| ID | 需求 | 验收标准 | 优先级 |
|---|---|---|---|
| R4.1 | 通道绑定管理：成员的小程序 openid / 手机号（预留）统一挂到 user | 支持解绑与重绑；服务号 openid 升个体户后补 | P0 |
| R4.2 | 三级触达路由：强（接送/变更→订阅消息）、中（打卡提醒/周报→订阅消息）、弱（不推） | 路由规则可配置，按成员角色有默认值（祖辈默认强触达全开）；服务号/短信兜底升个体户后恢复 | P0 |
| R4.3 | 送达升级：强触达消息带小程序跳转，**点击打开=确认回执**（微信无已读回执）；15 分钟无回执 → 应用内待办红点；30 分钟无回执 → 通知备份联系人（配偶）的订阅消息 | 创建日程到祖辈收到提醒 <1 分钟；订阅消息到达率/回执率作为 Phase 0 在验指标（订阅消息无 99% 保证） | P0 |
| R4.4 | 免打扰：22:00–7:00 仅放行强触达 | 用户可自定义时段 | P1 |

| ID | 需求 | 验收标准 | 优先级 |
|---|---|---|---|
| R6.1 | 日程/打卡下评论：仅家庭成员可见，承载上下文沟通（"今天钢琴课改到 6 点"） | 评论触发中等级触达给相关责任人 | P1 |

**不做独立 IM**：家庭闲聊在微信群里已经很好，不重复造；评论只解决"挂在上下文上的沟通"。

## 7. V1 明确不做（边界）

- 无广场、无圈子、无陌生人社交（全部留给 V3）
- 无任何排名/跨家庭对比（设计红线）
- **无激励体系**（积分/心愿/游戏化后置，架构上预留事件钩子，见 M3）
- 无外部成员角色（家教/阿姨 → V2）
- 无变现（成长报告订阅、打印 → V2+ 再评估）
- 不做独立 IM；不做 App（父母 push 需求 V2 验证后再上）

## 8. 非功能需求

- 合规：未成年人数据加密存储、展示脱敏；家长可导出/删除孩子数据（个保法要求）
- 性能：小程序首屏 <2s（祖辈手机普遍中低端）
- 可观测：触达成功率看板（分通道/分级别）从第一天就要有，这是本产品的生命线指标
- 北极星：**周活跃协作家庭数**（当周有日程创建或打卡完成的家庭）；次级：单家庭平均成员数、强触达确认率
