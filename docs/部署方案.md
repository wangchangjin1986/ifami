# ifami 部署方案（Phase 0 最小落地）

> 执行口径：**一台 ECS 本机原生跑全部自有组件**——MySQL / Redis / Caddy / ifami（api+worker）全部装在一台 ECS 上，api/worker 用 systemd 守护，**不装 Docker**；托管只保留 TOS（起步省钱，数据可靠性靠定期备份兜底、规模化切 RDS；计算编排压到最简）。目标架构与恢复时机见 [技术方案设计.md](技术方案设计.md) §10。

## 1. 火山引擎资源清单

| 资源 | 规格 | 用途 | 月成本量级 |
|---|---|---|---|
| ECS | 2C4G，40G 系统盘，按量或包年 | api + worker + redis + caddy + mysql（本机原生，systemd 管理） | ~¥150 |
| MySQL | Phase 0 本机安装（ECS 上，见 §3.7 备份） | 全部业务数据（后续规模化切 RDS） | ¥0 |
| Redis | Phase 0 本机安装（ECS 上，纯缓存可丢） | 会话/缓存 | ¥0 |
| TOS 对象存储 | 标准存储 + 按量 | 打卡照片、课表原图（签名 URL 防盗链） | <¥10 |
| 域名 | 1 个（如 `ifami.site`） | 需 **ICP 备案**（小程序合法域名的前提） | ~¥55/年 |
| SSL 证书 | Caddy 自动签发（Let's Encrypt） | 小程序强制 HTTPS | ¥0 |
| 短信服务 | 按量，签名需报备 | 强触达兜底（**暂缓**：纯个人主体无法报备签名，升个体户后启用） | ~¥0.045/条 |
| 弹性公网 IP | 1 个，绑 ECS | 入口 | ~¥20 |
| **合计** | | | **≈ ¥200/月以内** |

明确不买（Phase 0）：VKE、CLB/APIG、托管 Redis、托管 MySQL（RDS）、BMQ/RocketMQ、TLS/APMPlus——用云监控免费额度 + 应用自建指标替代。

## 2. 网络与拓扑

```
微信客户端(小程序/服务号H5)
      │ HTTPS（仅 443）
      ▼
域名 api.ifami.site → EIP → ECS:Caddy(自动HTTPS,反代,本机运行)
                              ├─→ 127.0.0.1:8080  (Hertz，REST API，systemd: ifami-api)
                              ├─→ /h5/* → 静态文件(服务号周报/邀请落地页)
                              └─→ /wechat/callback → api(微信消息推送回调)
本机进程: api/worker → 127.0.0.1:6379 (Redis)      api/worker → 127.0.0.1:3306 (MySQL)
出向:    api/worker → TOS(内网Endpoint) / 微信API / 短信网关 / 火山方舟
```

ECS 安全组只放 80/443/22（22 限办公网 IP），不放 3306/6379；MySQL、Redis 均只监听 127.0.0.1，TOS 走内网 Endpoint，不出公网。

## 3. 后端部署

### 3.1 仓库结构（单仓单二进制）

```
ifami/
├── cmd/ifami/main.go        # serve api | serve worker | migrate
├── internal/
│   ├── identity/ schedule/ task/ notify/ growth/ ingest/   # 模块边界=未来服务边界
│   └── pkg/                 # db, redis, wechat-sdk, auth middleware
├── migrations/              # golang-migrate SQL
├── deploy/
│   ├── ifami-api.service  ifami-worker.service  caddy.service   # systemd 单元
│   ├── Caddyfile  deploy.sh  bootstrap.sh  .env.example  backup.sh
└── miniapp/                 # 微信小程序前端
```

### 3.2 编译（go build，单二进制双模式）

```bash
CGO_ENABLED=0 go build -o ifami ./cmd/ifami   # 同一二进制，serve 子命令区分进程
./ifami migrate                               # 建表（幂等，读 .env 的 RDS_DSN + MIGRATIONS_DIR）
```

### 3.3 systemd 单元（本机守护 api / worker）

`deploy/ifami-api.service` / `deploy/ifami-worker.service`：`EnvironmentFile=/opt/ifami/deploy/.env`，`ExecStart=/opt/ifami/ifami serve api|worker`，`Restart=always`。`deploy/caddy.service`：以 caddy 用户运行、`AmbientCapabilities=CAP_NET_BIND_SERVICE` 绑 80/443。MySQL / Redis 用发行版服务管理（`mysql` / `redis-server`）。首次初始化统一走 `deploy/bootstrap.sh`。

### 3.4 Caddyfile

```
api.ifami.site {
    handle /h5/* {
        root * /opt/ifami/h5
        file_server
    }
    handle {
        reverse_proxy 127.0.0.1:8080
    }
}
```

### 3.5 发布流程（deploy.sh）

```
本地 push 代码 → ssh ECS → git pull → go build → ifami migrate →
service.sh restart api worker → 健康检查 /healthz
```

- 脚本分工：`bootstrap.sh` 只做首次初始化（中间件检测、建库建账号、systemd 单元安装）；`deploy.sh` 负责日常迭代的编译与发布（含停服重启，起停动作委托 `service.sh`）；`service.sh` 是服务起停/日志的唯一入口（支持 `start|stop|restart|status [api|worker|caddy]` 按组件操作）。

- 数据库迁移先行且幂等（golang-migrate）；失败不切换流量（systemd `Restart=always` 兜底，Phase 0 接受秒级中断）。
- 回滚 = `git checkout <上个tag>` 重跑发布脚本；每个发布打 git tag。

### 3.6 配置与密钥

`.env`（权限 600，不进仓）：微信 AppID/Secret（小程序；服务号升个体户后加）、MySQL DSN（本机，`127.0.0.1:3306`）、`MYSQL_ROOT_PASSWORD`（backup.sh 用）、TOS AK/SK、短信密钥（升个体户后启用）、方舟 API Key、字段加密密钥、`REDIS_ADDR`（本机 6379）、`MIGRATIONS_DIR`。`.env.example` 进仓。

> systemd 的 `EnvironmentFile` 只做字面 `KEY=value` 解析，不做 shell 展开：`.env` 里密钥必须是**生成好的字面值**，不能写 `FIELD_ENC_KEY=$(openssl …)`。

### 3.7 备份与恢复

- MySQL（本机）：`deploy/backup.sh` 每日 mysqldump（建议 cron），每月演练一次恢复。
- TOS：开版本控制，误删可恢复。
- ECS 本体无状态，重建 = 重跑部署脚本 + 装依赖。

## 4. 前端部署

### 4.1 小程序

| 步骤 | 说明 |
|---|---|
| 1. 主体与认证 | 个人主体注册小程序（无需认证，¥0；无 `getPhoneNumber`） |
| 2. 合法域名 | 后台配置 request / uploadFile / downloadFile 域名：`https://api.ifami.site`（要求 ICP 备案 + HTTPS） |
| 3. 隐私协议 | 声明手机号、相册、摄像头用途（打卡拍照/课表识别） |
| 4. 类目 | 工具 → 效率/生活服务类目（个人可过审）；打卡照片属 UGC，须接内容安全检测（`mediaCheckAsync`）否则审核被拒 |
| 5. 日常发布 | 开发者工具或 **miniprogram-ci** 上传 → 体验版（家人扫码即用，Phase 0 主通道）→ 提审 → 全量 |

Phase 0 不急着过审上架：体验版支持最多 100 个体验成员，自己家 + 朋友家够用；正式上架在 Phase 1 结束前完成。

### 4.2 服务号 H5（周报/邀请落地页）——暂缓，升个体户后启用

- 静态页面放仓库 `h5/`，由本机 Caddy 直出 `api.ifami.site/h5/*`（`root /opt/ifami/h5`）。邀请卡片落地页 Phase 0 即可复用。
- 服务号后台（升个体户后）：服务器配置 URL 指向 `https://api.ifami.site/wechat/callback`（api 进程处理消息推送与模板消息回执）；网页授权域名同域。
- 模板消息跳转小程序：用 `miniprogram` 跳转参数，路径即回执上报页。

### 4.3 前后端版本兼容

- API 路径带版本前缀 `/v1/`；小程序发版与后端发版的兼容矩阵记录在仓（`miniapp/COMPAT.md`）。
- 后端先发、小程序后发；接口只增不改，废弃字段留一个版本周期。

## 5. 最小监控

- **存活**：火山云监控 HTTP 探测 `https://api.ifami.site/healthz`（1 分钟粒度，异常短信告警到创始人手机）。
- **触达看板（P0 生命线）**：worker 每 10 分钟汇总 `notify_jobs`（分通道成功率/回执率/升级率）写库；Phase 0 的"看板"= 每日 21:00 把当日汇总推送到创始人自己的服务号——零前端成本。
- **日志**：api/worker 落盘 `/var/log/ifami-api.log` / `/var/log/ifami-worker.log`（systemd `append:` 重定向），logrotate 每日轮转留 14 天（`deploy/ifami.logrotate`，bootstrap 自动安装）；journald 仍有一份兜底（`journalctl -u ifami-api`）。Phase 1 再迁 TLS。
