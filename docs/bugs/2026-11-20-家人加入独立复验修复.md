本轮处理 CoCo-CR 对 `25b5e4b..9b6533b` 确认的两项 P1、一项 P2，修复增量从 `9b6533b` 起。未改变批准的四步加入、24 小时凭据、成员权限或单家庭规则；未新增接口、数据库迁移、外部依赖或 join_attempt。

## P1：并发错误码试探超过失败阈值

原实现先只读检查失败次数，查码失败后才递增。让 64 个请求同时完成检查再查码，真实 Redis 出现 64 次实际查码、0 次限流。

改为 Redis Lua 原子检查并占用 user/IP 两个预算；正在查码的请求与已失败请求共同占用预算。验证成功、或取得预算后的技术故障会归还，错误输入保留计数。完成动作只执行一次，窗口代际元数据防止迟到归还扣除新窗口计数。预算为空时清理空窗口；已有失败计数与原到期时间保留，不因成功请求滑动续期。Redis 故障继续拒绝授权，无法确认的占用依靠原窗口过期。

内部 registry 的 Allow/Failed 改为 Reserve/Finish；公开 HTTP 契约没有改变。窗口元数据属于现有失败计数，未新增逐次加入结果登记或成员/换码使用配额。

真实 Redis 命令屏障回归同时覆盖 preview/confirm：

| 64 并发场景 | 实际进入查码 | 被拒绝 |
|---|---:|---:|
| 相同用户 | 10 | 54 |
| 不同用户、相同 IP | 30 | 34 |

另覆盖成功查码不花费失败额度、旧窗口归还不影响新窗口、现有计数/TTL 保留、取消请求归还和重复完成不重复归还。测试使用任务专用 namespace，不清空共享 Redis。

## P1：重新校验或修改输入丢失未知加入结果

原页面把待核对家庭与可编辑 preview 绑定；重新校验清空 preview、改码清空未知标志，导致恢复入口消失或跳过成功的 `/me` 核对重发。

本轮独立保存原提交目标家庭。未知结果期间，重新校验、手输改码、扫码及确认入口都先核对原目标；查询不可用时保留目标和独立恢复入口，不查询新码或再次 POST。只有成功确认原关系不存在才可校验/提交当前新码；若已加入，按服务端实际 membership 落地。提交期间锁住输入，原码过期或可编辑 preview 清空不影响恢复。页面在未知结果时显示“核对加入结果”入口。

## P2：旧 DELETE 响应清空新代面板

作废请求现在与 GET/POST 共用请求序号、当前家庭与面板状态检查。关闭或进入后台会使旧请求失效；旧 DELETE 的成功、失败回包均不会修改新码或发起额外读取。
