# 加入预算 Redis 重试幂等修复（2026-11-23）

本轮继续处理 CoCo-CR 在 `e50a623` 确认的 P1：预算归还已执行但响应丢失时，go-redis 默认重发同一次 Eval，本地 sync.Once 无法阻止 Lua 再次归还，计数 2→1→0，擦掉另一条失败。

## 修复

- 每次 Reserve 生成唯一预算操作 ID，在同一次 Lua 中记录所用计数键、窗口标识和完成标记。库内部重发使用同一 ID，返回原占用，不再次增加计数。
- Finish 在 Redis 内检查 ID 与窗口，先标记完成，再归还预算；重复 Eval 直接返回已完成，不能再次扣减。回执缺失或错配时拒绝归还。
- 已完成或窗口已变化的 Reserve 回执不能再次授权占用；迟到 Finish 继续受原窗口标识限制。
- 回执有 TTL（保护窗口，至少 60 秒），重复命令不续期。它只记录预算命令幂等信息，不保存家庭、加入码、角色、membership 或业务加入结果。
- go-redis 的全局重试配置、HTTP 接口、原失败阈值与成员权限均未改变。没有新增数据库迁移或依赖。

## 真实 Redis 验证

测试先读取真实 Redis 响应，再丢弃并返回 EOF，由生产默认重试循环自动重发；没有在应用代码中手工调用两次 Eval。

| 场景 | 实际 Eval 次数 | 修复结果 |
|---|---:|---|
| Finish 丢一次响应 | 2 | 只归还一次，另一条失败仍为 1 |
| Finish 四次响应全部丢失 | 4 | 调用返回不可用，另一条失败仍为 1 |
| Reserve 丢一次响应 | 2 | 只占用一个预算 |
| Reserve 四次响应全部丢失 | 4 | 调用返回不可用，仍只占用一个预算 |

此外覆盖回执被移除后禁止归还，以及响应丢失期间预算窗口改变时旧 Reserve 重试失败关闭。原并发 64 请求用例继续通过：同用户实际查码 10/拒绝 54，同 IP 不同用户实际查码 30/拒绝 34。
