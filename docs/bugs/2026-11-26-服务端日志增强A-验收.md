日期：2026-11-26。设计提交897be3f，实施基于main 05fcf87。工作树：/tmp/ifami-logging-plan-20261126，分支feat/server-logging-20261126。当前未推送、未部署。

## 已实现

- 标准库slog JSON，日志带service/version/event与级别；不可变request_id上下文、鉴权后user_id、HTTP业务code摘要。请求头家庭编号标记为requested_family_id，验证权限后才给依赖操作family_id。
- Redis Eval错误在映射1012前记录稳定操作名及安全原因；原Lua/参数/客户端重试与Reserve/Finish预算幂等不变。限流WARN仅限日志频率，业务拒绝逻辑不变。
- GORM错误/慢查询记录耗时、行数、数值错误码与安全代码位置；不记录原始SQL/参数。已关闭日志级别提前返回，避免无效日志字段工作。
- 微信/方舟记录操作耗时、HTTP失败与厂商业务码；CodedError保留原有公共Error()/Unwrap()行为，只为诊断提供安全分类。原始HTTP/厂商请求响应数据不输出。
- Worker扫描batch_id、任务run_id和job_type/job_id；持久化成功后记录状态。识别后台只复制安全日志元数据，继续脱离请求取消；跨重启用持久化job_id关联，不增加迁移。
- 框架异常保留安全bind/permission/DNS/timeout等分类与代码位置，panic正文不输出。请求panic诊断记录路由、已鉴权用户、状态及耗时，再重抛，保持原框架恢复语义。
- startup版本诊断及有界Redis版本读取；失败只警告不新增启动门禁。保留现有systemd日志文件和轮转，补操作手册及LOG_LEVEL示例。

## 开销与局限

合成HTTP固定1ms handler、4并发、1200次请求、INFO写本地文件，基线与最终源各运行5轮交错测量，取中位数；不是线上或完整数据库负载。

| 指标 | 原文本访问日志 | 最终JSON日志 |
|---|---:|---:|
| p50 | 1.182 ms | 1.180 ms |
| p95 | 1.391 ms | 1.334 ms |
| 单轮CPU时间 | 91.59 ms | 87.84 ms |
| 进程峰值RSS | 20.70 MiB | 20.97 MiB |
| 每请求日志量 | 272.2 B | 484.9 B |

首轮p95约+18%，减少关闭级别日志工作和字段分配后中间复测约+10%，最终复测约-4%。这说明短时合成负载受调度/运行环境波动影响，不能把最终负值解释为性能收益，亦不能据此保证线上p95增幅≤5%。保留每轮原始结果，部署后须观察实际接口、CPU、磁盘和日志量。

JSON访问日志量约为旧格式1.8倍；DEBUG还有更多成功依赖事件，排障后应恢复INFO。日志同步写文件，慢盘仍可能增加耗时；写失败不改变业务返回值，copytruncate仍可能丢行。无trace/采集器/查询平台、无迁移/权限/业务状态或重试策略变化。

真实微信送达/授权、真机交互与24小时联网生命周期未执行；本轮没有部署/线上验证。原共享工作区的既有业务修改未覆盖。
